# Развёртывание SOVLI v1.3.0 только с телефона

Эта версия рассчитана на Render Free Web Service + внешнюю базу Neon. Render запускает Node.js и Socket.IO; Neon хранит постоянный снимок данных, поэтому аккаунты и балансы не зависят от временного диска Render.

## Что понадобится

- Аккаунт GitHub с репозиторием `Slabenk1y/solvi-chat`.
- Аккаунт Render.
- Уже созданный проект Neon.
- Pooled connection string Neon. Это секретная строка PostgreSQL, начинающаяся с `postgresql://`. Не отправляй её в чат.

## Шаг 1. Подготовь Neon

1. Открой Neon Console и выбери существующий проект.
2. Нажми **Connect**.
3. Выбери нужную branch, database и role.
4. Включи pooled connection, если переключатель показывается.
5. Скопируй connection string. Сохрани его в буфер обмена телефона; не публикуй его.

Если консоль Neon не открывается, код проекта можно подготовить заранее, но облачный запуск с постоянным хранением нельзя завершить без этой строки подключения.

## Шаг 2. Подготовь Render Environment

1. Открой Render Dashboard → существующий сервис `sovli-chat` → **Environment**.
2. Добавь `DATABASE_URL` и вставь connection string Neon.
3. Убедись, что задан `JWT_SECRET` — длинный случайный секрет. Не меняй его после настройки.
4. Убедись, что `OWNER_PUBLIC_ID` совпадает с Public ID твоего аккаунта SOVLI.
5. Сохрани изменения.

Не вставляй connection string в GitHub, исходники, `.env.example` или чат.

## Шаг 3. Обнови проект

1. Открой GitHub → `Slabenk1y/solvi-chat`.
2. Проверь, что изменения версии 1.3.0 находятся в `main`.
3. В Render открой сервис → **Manual Deploy** → **Deploy latest commit** (или дождись автоматического deploy после обновления main).
4. В Deploy Logs дождись сообщения о восстановлении или создании постоянной копии Neon и успешного запуска сервера.

Если `DATABASE_URL` отсутствует, новая версия на Render намеренно завершит запуск с понятной ошибкой, а не будет работать на временной базе.

## Шаг 4. Проверь сайт и панель владельца

1. Открой `https://<твой-сервис>.onrender.com/api/health`.
2. В ответе найди `"persistentStorage":true`.
3. Открой главную страницу и войди в свой аккаунт.
4. Открой `/owner`. Проверь список пользователей и экономику.

При первом запуске Neon snapshot создаётся из SQLite-файла, доступного новой версии в момент запуска. При следующих рестартах база восстанавливается из Neon, а Public ID аккаунта владельца сохраняется.

## Как хранятся данные

- Аккаунты, сессии, профиль, балансы, магазин, промокоды, жалобы и журнал владельца попадают в снимок Neon.
- Пользовательские аватары сохраняются в снимке (до 2 МБ на файл, до 48 МБ суммарно).
- Активные диалоги, сообщения и временные медиа по-прежнему очищаются при перезапуске сервера согласно политике приложения.
- Снимок обновляется после изменений с короткой задержкой и дополнительно при штатной остановке.
- Работает один экземпляр сервиса; не включай горизонтальное масштабирование.

## Ограничения бесплатного Render

Бесплатный Render засыпает после 15 минут без входящего трафика. Первый запрос после сна может ждать около минуты, пока сервер проснётся. Render Free не сохраняет файлы локального диска при перезапуске — именно поэтому постоянные данные лежат в Neon.

## Управление Render с телефона

После настройки `RENDER_API_KEY` и соответствующих GitHub Actions secrets вкладка «Облачный сервер» в `/owner` сможет управлять запущенным сервисом. Это необязательная функция и не нужна для сохранения аккаунтов.

## Безопасность

Не отправляй в чат или GitHub секреты `DATABASE_URL`, `JWT_SECRET`, `RENDER_API_KEY`, пароли и резервные копии.
